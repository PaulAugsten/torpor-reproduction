# Figure 10: end-to-end comparison (4 GPUs)

Three bars per function count (40, 80, 120, 160): Native, Torpor and INFless-KA
(keep-alive). All three replay the same Azure-derived trace
(`../../tools/req_arrivals_<n>_5min_trace.npy`, generated by the first Native
run at each count), so Native must run first. `figure10_analyze_router_log.py`
reports latency and SLO attainment: the share of functions whose P98 latency
is within 80 ms. General porting notes are in [`../README.md`](../README.md).

## Run everything

```bash
mkdir -p logs_batch && sbatch -A <project> sbatch_figure10.sh
# or interactively on a compute node, venv active:
./run_all_figure10.sh <FUNC_NUM> # one count, all three bars;
                                 # wipes previous logs first (KEEP_LOGS=1 keeps them)
```

## Individual bars

```bash
./run_fig10_native.sh <FUNC_NUM>   # also generates the shared trace
./run_fig10_torpor.sh <FUNC_NUM>
./run_fig10_ka.sh <FUNC_NUM>       # needs the Native trace for that FUNC_NUM
```

Outputs: `logs_fig10/{native,torpor,ka}_<n>_result.txt` (summaries), plus the
router and server logs of each run next to them.

## Notes

- Native hosts at most 72 functions (18 per GPU). The cap is upstream's
  `MAX_CONTAINERS = 72` in `evaluation2/figure10/baseline_native.py`, kept
  unchanged. INFless-KA has the equivalent upstream constant
  `max_model_num_per_server = 18`.
- The analyzer uses an 80 ms deadline (the paper's value for CV models);
  upstream's analyzer uses 100 ms. The reported table is identical under both.
- The keep-alive baseline terminates idle endpoints with `pkill` instead of
  `docker stop`. Terminations run on their own thread pool, and functions
  waiting for termination are not selected again. Upstream shares one pool
  for launches and terminations.
- `sender_from_trace.py` regenerates a cached trace that references function
  ids beyond the current function count.
